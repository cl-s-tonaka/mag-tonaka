## 1. エグゼクティブサマリー

### 1.1 プロジェクト概要

静的なGitHub PRベースのエージェント生成から、API経由の動的エージェント登録アーキテクチャへの移行プロジェクト。

**現状の課題**:
- 新しいエージェントを追加するにはコードベースの変更とサーバー再起動が必要
- GitHub PRのマージを待つ必要があり、即座に利用できない
- ユーザーが直接エージェントを作成・管理できない

**提案する解決策**:
- API経由で動的にエージェントを登録可能
- 再起動不要で即座に利用可能
- 既存システムに影響を与えない独立したアーキテクチャ（Strategy B）

### 1.2 ビジネス価値

| メトリクス | 現状 | 目標 |
|----------|------|------|
| **エージェント追加時間** | 数時間〜数日（PR → レビュー → マージ → デプロイ） | 数秒（API呼び出しのみ） |
| **ユーザー自律性** | なし（開発者のみ） | あり（エンドユーザーも可能） |
| **システム可用性** | 再起動時にダウンタイム | 常時稼働（再起動不要） |
| **開発生産性** | 実験的エージェントに高コスト | 低コストで迅速な実験 |

### 1.3 スコープ

**対象範囲（In Scope）**:
- 動的エージェントの作成・読取・更新・削除（CRUD）
- 動的ツールの作成と実行
- データベースへの永続化
- サーバー再起動時の自動復元
- セキュリティサンドボックス（VM2）
- 基本的な認証・認可
- 監査ログ

**対象外範囲（Out of Scope - 将来の拡張）**:
- 動的エージェントのバージョン管理
- 動的エージェント間の依存関係管理
- 高度なパフォーマンス最適化（Worker Threads）
- フロントエンドUI（MVPではAPI のみ）
- マーケットプレイス機能

## 2. ビジネス要件

### 2.1 目標

#### プライマリーゴール

**BG-001: 即時性**
- **説明**: エージェント作成からユーザーが利用可能になるまでの時間を最小化
- **現状**: 数時間〜数日
- **目標**: 5秒以内
- **測定方法**: API呼び出しから`voltAgent.registerAgent()`完了までの時間

**BG-002: 自律性**
- **説明**: ユーザーが開発者の介入なしにエージェントを作成可能
- **現状**: 不可能（開発者のみ）
- **目標**: エンドユーザーがAPIを通じて作成可能
- **測定方法**: ユーザー作成エージェント数 / 全エージェント数

**BG-003: 安全性**
- **説明**: 既存システムへの影響を完全に排除
- **現状**: N/A（新規機能）
- **目標**: 動的システムの障害が静的システムに影響を与えない
- **測定方法**: 障害分離率100%、既存エージェントのダウンタイム0

#### セカンダリーゴール

**BG-004: スケーラビリティ**
- **説明**: 多数の動的エージェントをサポート
- **目標**: 1000個以上の動的エージェントを性能劣化なくサポート

**BG-005: 保守性**
- **説明**: システムの保守と拡張が容易
- **目標**: 明確な責任分離、独立したテスト、簡単なロールバック

### 2.2 ステークホルダー

| ステークホルダー | 役割 | 期待 |
|----------------|------|------|
| **エンドユーザー** | システム利用者 | 即座にエージェントを作成・利用可能 |
| **開発者** | システム実装・保守 | 明確な設計、保守しやすいコード |
| **プロダクトマネージャー** | ビジネス要件管理 | ユーザー価値の最大化、迅速なリリース |
| **セキュリティエンジニア** | セキュリティ監査 | 安全な動的コード実行 |
| **DevOps/SRE** | 運用・監視 | 安定稼働、簡単なロールバック |

### 2.3 成功基準

**MVP（Minimum Viable Product）**:
- [ ] 動的エージェントの作成・保存・実行が可能
- [ ] サーバー再起動後も永続化される
- [ ] 基本的な動的ツールが実行可能
- [ ] VM2サンドボックスが動作

**フル実装**:
- [ ] 完全なCRUD API
- [ ] フィーチャーフラグで段階的ロールアウト
- [ ] プロダクション環境で1週間安定稼働
- [ ] 既存エージェントに影響なし

## 3. 機能要件

### 3.1 動的エージェント管理

#### FR-001: エージェント作成

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a ユーザー
I want API経由でエージェントを作成したい
So that 開発者の介入なしに新しいエージェントを利用できる
```

**受入基準**:
- [ ] `POST /api/v2/dynamic-agents` でエージェント作成
- [ ] 必須フィールド: `agentId`, `displayName`, `description`, `instructions`
- [ ] オプションフィールド: `model`, `tools`, `testExamples`
- [ ] 作成後即座に`voltAgent.registerAgent()`で登録
- [ ] データベースに永続化
- [ ] 成功時に`agentId`を含むレスポンスを返す

**エラーハンドリング**:
- 重複`agentId`: 409 Conflict
- バリデーション失敗: 400 Bad Request
- DB保存失敗: 500 Internal Server Error

#### FR-002: エージェント一覧取得

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a ユーザー
I want 全エージェント（静的+動的）の一覧を取得したい
So that 利用可能なエージェントを確認できる
```

**受入基準**:
- [ ] `GET /api/agents-with-examples` で静的+動的エージェントを返す
- [ ] 各エージェントの基本情報（id, displayName, description）を含む
- [ ] 動的エージェントには`isDynamic: true`フラグを付与
- [ ] ステータス`active`のエージェントのみ返す

#### FR-003: エージェント詳細取得

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a ユーザー
I want 特定のエージェントの詳細情報を取得したい
So that エージェントの機能を理解できる
```

**受入基準**:
- [ ] `GET /api/v2/dynamic-agents/:id` でエージェント詳細を返す
- [ ] エージェント定義、ツール一覧、テスト例を含む
- [ ] 存在しないIDの場合: 404 Not Found

#### FR-004: エージェント更新

**優先度**: 高（Should Have）

**ユーザーストーリー**:
```
As a ユーザー
I want 既存の動的エージェントを更新したい
So that エージェントの機能を改善できる
```

**受入基準**:
- [ ] `PUT /api/v2/dynamic-agents/:id` でエージェント更新
- [ ] 更新可能フィールド: `displayName`, `description`, `instructions`, `tools`
- [ ] バージョン番号を自動インクリメント
- [ ] `voltAgent.registerAgent()`で再登録
- [ ] 監査ログに記録

#### FR-005: エージェント削除

**優先度**: 高（Should Have）

**ユーザーストーリー**:
```
As a ユーザー
I want 不要な動的エージェントを削除したい
So that システムをクリーンに保てる
```

**受入基準**:
- [ ] `DELETE /api/v2/dynamic-agents/:id` でエージェント削除
- [ ] 論理削除（status = 'deleted'）
- [ ] `voltAgent.unregisterAgent()`で登録解除
- [ ] カスケード削除: 関連ツール、テスト例
- [ ] 監査ログに記録

#### FR-006: エージェント無効化/有効化

**優先度**: 中（Could Have）

**ユーザーストーリー**:
```
As a ユーザー
I want エージェントを削除せずに一時的に無効化したい
So that 後で再有効化できる
```

**受入基準**:
- [ ] `POST /api/v2/dynamic-agents/:id/disable` で無効化
- [ ] `POST /api/v2/dynamic-agents/:id/enable` で有効化
- [ ] 無効化中は`voltAgent`から登録解除
- [ ] エージェント一覧に表示されない

### 3.2 動的ツール管理

#### FR-101: ツール作成

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a ユーザー
I want エージェントにカスタムツールを追加したい
So that エージェントに特定の機能を実装できる
```

**受入基準**:
- [ ] エージェント作成時に`tools`配列でツール定義
- [ ] 各ツールは`name`, `description`, `parameters`, `implementation`を含む
- [ ] `implementation`はJavaScript関数文字列
- [ ] VM2サンドボックスでコンパイル
- [ ] Zodスキーマでパラメータバリデーション

**ツール定義例**:
```json
{
  "name": "add",
  "description": "Add two numbers",
  "parameters": [
    {"name": "a", "zodType": "number", "description": "First number"},
    {"name": "b", "zodType": "number", "description": "Second number"}
  ],
  "implementation": "return { result: a + b };"
}
```

#### FR-102: ツール実行

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a エージェント
I want ツールを安全に実行したい
So that ユーザーの要求に応えられる
```

**受入基準**:
- [ ] VM2サンドボックス環境で実行
- [ ] タイムアウト5秒
- [ ] 許可されたAPIのみアクセス可能（fetch, console）
- [ ] エラーをキャッチして適切にハンドル

#### FR-103: ツール更新

**優先度**: 中（Could Have）

**ユーザーストーリー**:
```
As a ユーザー
I want エージェントのツールを更新したい
So that ツールの実装を改善できる
```

**受入基準**:
- [ ] エージェント更新時にツールも更新
- [ ] 既存ツールの修正・削除・追加をサポート
- [ ] エージェントインスタンスを再生成

### 3.3 エージェント実行

#### FR-201: エージェント実行

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a ユーザー
I want 動的エージェントにタスクを実行させたい
So that エージェントの機能を利用できる
```

**受入基準**:
- [ ] `POST /api/agents/:agentId/execute` で実行
- [ ] リクエストボディ: `{ "task": "...", "context": "..." }`
- [ ] VoltAgent Agentの`run()`メソッドを呼び出し
- [ ] ストリーミングレスポンス対応
- [ ] 実行結果を返す

#### FR-202: 実行履歴

**優先度**: 低（Won't Have - MVP）

**ユーザーストーリー**:
```
As a ユーザー
I want エージェントの実行履歴を確認したい
So that エージェントの利用状況を把握できる
```

**受入基準**:
- [ ] 実行日時、タスク、結果を記録
- [ ] `GET /api/v2/dynamic-agents/:id/executions` で取得
- [ ] ページネーション対応

### 3.4 永続化と復元

#### FR-301: データベース永続化

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a システム
I want 動的エージェント定義をデータベースに保存したい
So that サーバー再起動後も利用可能
```

**受入基準**:
- [ ] `dynamic_agents.db`に保存
- [ ] エージェント定義、ツール定義、テスト例を保存
- [ ] トランザクション対応

#### FR-302: 自動復元

**優先度**: 必須（Must Have）

**ユーザーストーリー**:
```
As a システム
I want サーバー起動時に動的エージェントを自動復元したい
So that ユーザーが再登録する必要がない
```

**受入基準**:
- [ ] サーバー起動時に`DynamicAgentManager.loadDynamicAgents()`実行
- [ ] ステータス`active`のエージェントのみロード
- [ ] 各エージェントを`voltAgent.registerAgent()`で登録
- [ ] 起動ログに復元されたエージェント数を出力

## 5. 制約条件

### 5.1 技術的制約

| 制約 | 説明 |
|-----|------|
| **VoltAgentフレームワーク** | `voltAgent.registerAgent()`のAPIに依存 |
| **LibSQL** | データベースはLibSQL（Turso）を使用 |
| **Node.js** | Node.js 18+ |
| **VM2** | MVPではVM2サンドボックスを使用（将来Worker Threadsへ移行） |

### 5.2 ビジネス制約

| 制約 | 説明 |
|-----|------|
| **既存システム影響ゼロ** | 静的エージェントに影響を与えない |
| **段階的ロールアウト** | MVP → 限定ユーザー → 全体 |
| **予算** | 追加インフラコストなし（既存サーバー内で実装） |

### 5.3 時間的制約

| フェーズ | 期間 |
|---------|------|
| **MVP** | 3-4日 |
| **フル実装** | 2-3週間 |
| **プロダクション対応** | +1週間 |

## 7. リスクとその軽減策

### 7.1 技術的リスク

| リスク | 確率 | 影響 | 軽減策 |
|-------|-----|------|-------|
| **任意コード実行脆弱性** | 中 | 致命的 | VM2サンドボックス、Worker Threads、厳格な入力バリデーション |
| **VoltAgent統合失敗** | 中 | 高 | 早期プロトタイプで検証、VoltAgent APIドキュメント確認 |
| **パフォーマンス劣化** | 低 | 中 | 遅延ロード、キャッシング、パフォーマンステスト |
| **DB移行失敗** | 低 | 高 | 専用DB（dynamic_agents.db）で完全分離 |

### 7.2 ビジネスリスク

| リスク | 確率 | 影響 | 軽減策 |
|-------|-----|------|-------|
| **既存システムへの影響** | 低 | 致命的 | Strategy B（完全分離）、フィーチャーフラグ、段階的ロールアウト |
| **実装期間超過** | 中 | 中 | MVPファーストアプローチ、明確なマイルストーン |
| **ユーザー採用率低下** | 低 | 中 | ユーザーフィードバック収集、UI/UX改善 |

| **動的エージェントのバージョン管理** | 低 | MVPでは最新バージョンのみサポート |
| **動的エージェント間の依存関係** | 低 | 複雑性が高い、需要不明 |
| **マーケットプレイス機能** | 低 | ビジネスモデル未確定 |
| **フロントエンドUI** | 中 | MVPではAPI のみ、将来的にUI追加 |
| **Worker Threads隔離** | 中 | MVPではVM2、プロダクション対応時に検討 |
| **高度な分析・レポート** | 低 | 基本的な監査ログのみMVPに含む |
